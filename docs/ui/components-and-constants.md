Two services, two kinds of signal:

- `state/game-state.service.ts` (`GameStateService`, the facade over the client's one model, never a second one)
  holds only **derived** signals. Nothing the HUD reads is interpolated, so the round, roster, ranking, seats,
  session config and live balance are derived from the newest `game_state` / `game_snapshot` / `balance_updated`,
  which `MultiplayerService` already mirrors as signals; `WorldStore` stays the per-frame interpolated world the
  renderer draws, and the own-cell signals below read it through the render seam. `me` is this doc's shorthand;
  the signal is named `ownPlayerId` (the lint bar refuses a two-letter name). The signals: `me`, `ownCell`, `ownProgress`, `balance` (the snapshot's `game_state.balance`), `threats`,
  `ownCellIndicators` (§3.1.4; `null` while spectating), `connectionState`, `serverError`, `resultsStartedAtTick`,
  `serverTickEstimate`, `lastAliveOwnCell` (the own cell of the last snapshot with `lifeState === 'alive'`, kept
  until the next alive snapshot; §3.3) and `cameraExtent` (a world-space rectangle written by the render loop each
  frame through `game-setup.ts`; §3.1.2 `threatsFor` reads it, and it is the only render-side fact the HUD consumes).
- `hud/hud-state.service.ts` (`HudStateService`) holds the **writable** UI signals: `previewTraitId`
  (`TraitId | null`), `openOverlay` (`'none' | 'menu' | 'leaderboard' | 'encyclopedia'`; the full leaderboard is an
  overlay, so there is no separate expanded flag), `encyclopediaReturnTo` (`'menu' | 'game'`: where the
  encyclopedia's Escape goes, encyclopedia.md §11.1) and the onboarding `reticleVisible` flag.

Tab does not add a listener: `input/keyboard-input.ts` is the only keyboard handler on the document (§4), and its
controller reports the hold through `onFullLeaderboardHeldChanged`, which `game-host.component.ts` hands to
`HudStateService.setFullLeaderboardHeld`. A release with the leaderboard already closed leaves the state alone.

The HUD ↔ Pixi crossings are exactly four, all wired in `game-setup.ts` so that `render/` never imports from
`hud/` or `state/` services: the renderer receives `previewTraitId`, `reticleVisible` and `ownCellIndicators` as
read-only signals, and writes `cameraExtent`. Nothing else crosses; the renderer draws the indicators from the
record alone and computes only geometry (rendering/own-cell-indicators.md §10).

## 10. The UI kit (#354)

The look every panel, menu and screen copies, set once. The ESC menu ([`overlays.md §3.5`](./overlays.md#35-menu-escape))
and the encyclopedia ([`encyclopedia.md §11`](./encyclopedia.md#11-encyclopedia)) are its first users and #356's
hold-Tab panel is the next; the respawn, results and lobby screens move onto it by their own tickets. Home
`packages/client/src/app/ui-kit/`. The HUD elements built before it (the leaderboard, the picker cards, the notice
rows) keep their stylesheets until a ticket moves them, but no new screen grows its own panel, button or row. The
encyclopedia's layout is pending decision #DECISION; nothing in this section is.

### 10.1 Tokens, and how components share them

- **One bridge.** A stylesheet cannot read a TypeScript constant, so the kit publishes its tokens as custom properties,
  the way layout.md §1 publishes the HUD's: `ui-kit/format/ui-css-variables.ts` → `uiStyleVariables()`, a pure map of
  every `--ui-…` property, pinned entry by entry and as an exact key set by its spec. It carries the type roles
  (`--ui-type-<role>` and `--ui-font-sans` / `--ui-font-mono`), the colour roles of
  visual-style/principles-and-palette.md §2 including the kit's (`--ui-text`, `--ui-panel-top`, `--ui-accent`, …) and
  every constant of the table below.
- **Surfaces.** `UiSurfaceDirective` (`[uiSurface]`) goes on the element a kit tree lives in: it observes the host's
  size, sets `--ui-scale` from `uiScaleFor(width, height)` and spreads `uiStyleVariables()`. `uiScaleFor` is layout.md
  §1's `hudScaleFor` moved into the kit with its four constants, formula unchanged. The HUD shell is a surface and
  sets `--hud-scale` from the same value; the type and colour entries leave `hudStyleVariables` for the kit map, so
  the HUD stylesheets read `--ui-type-…` and the `--ui-` colours and `--hud-…` keeps only HUD sizes. The lobby's
  encyclopedia host is a surface too. Every kit length is `calc(<px> * var(--ui-scale))`; the focus ring alone is
  never scaled.
- **Boundaries.** Kit components are standalone and `OnPush`, with signal inputs and outputs. They import nothing from
  `game/`, `encyclopedia/` or `@evolution/shared` (an ESLint `no-restricted-imports` rule on `ui-kit/**` holds that),
  know no game words and read only `var(--ui-…)`. A feature passes its text and its test id in (a `testId` input,
  rendered on the root control), so every id keeps its one home (`HUD_TEST_ID`, `ENCYCLOPEDIA_TEST_ID`).

| `UI_TRANSITION_MS`                                                                    | 120              | ms   | Hover, press and selection fades.                                                                        |
| `UI_PANEL_ENTER_MS`                                                                   | 160              | ms   | A modal panel fades in rising `UI_SPACE_S_PX`, its scrim fading with it.                                 |

| State    | Look                                                                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

kit part takes is [`visual-style/ui-type.md §7`](../visual-style/ui-type.md#7-ui-colours-and-type).
