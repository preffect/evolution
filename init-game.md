## 1. Game Definition

- **Name:** Evolution
- **Theme / concept:** a single bioluminescent cell in a dark-field petri dish eats to grow, absorbs
  DNA from what it eats, picks traits on level-up, and engulfs smaller cells. "A single cell that
  becomes something more." ([`GDD.md §1`](./docs/GDD.md#1-core-fantasy))
- **Slug / host:** `evolution` → `evolution.preffect-ha.preffect-home.net`
- **Display title:** Evolution
- **Ports:** server 4400, client 4402 (from `PORTS.env`, no change)
- **Landing-card icon hue:** teal `#2dd4bf` (45,212,191): bioluminescent membrane green-blue, unused
  by the other cards. `new-game.sh` already inserted the card on the host; if it chose another free
  hue, keep the host's.
- **Player model:** max `ROOM_MAX_PLAYERS` (8); indexed avatars 0–5 map to the six player palettes
  of `docs/VISUAL-STYLE.md` (#34); no teams in build 1 (`mode: 'colony'` reserved, rejected).
- **Tick model:** real-time fixed step at `SIMULATION_TICK_HZ` = 60 (the template's `TICK_HZ`);
  `game_snapshot` every tick in build 1 (#32 may lower the broadcast rate; the simulation rate stays).
- **Win/lose / structure:** free-for-all rounds of `ROUND_DURATION_SECONDS`; winner = highest score;
  death = engulfed → 3 s spectate → respawn; results screen then automatic rematch with the next
  seed. ([`GDD.md §3`](./docs/GDD.md#3-session-structure-29))
- **Late-join:** allowed at any time, with catch-up ([`PROGRESSION.md §5`](./docs/PROGRESSION.md#5-late-join-catch-up)).
- **Persistence:** none.
- **Trust boundary:** local-only. The server owns positions, mass, eating, engulf resolution, DNA,
  levels, drafts, spawns, respawn and the leaderboard (everything in the snapshot). The client owns
  only its pointer target, sprint and trait-choice intents, plus cosmetic wobble, camera and
  interpolation. Inputs are validated by schema; nothing else is checked.
- **Determinism:** all simulation randomness comes from the seeded `RandomSource` (#73) forked per
  subsystem (`spawner`, `zones`, `traitDraft`, `spawnPlacement`); the manual `Clock` (#74) drives tests.

Fixed step order inside `stepWorld` (one tick):

1. apply latest inputs (target, sprint latch, trait choice)
2. round timer / phase (results freezes 3–9)
3. movement, then wall clamp, then soft separation
4. eating (motes, fragments, cap overflow)
5. metabolism (decay, photosynthesis, toxin, spikes)
6. engulf update (start, progress, release, payout, chains)
7. progression (level-ups, offer queue, timeouts)
8. spawners (food, fragments, detritus expiry)
9. respawn timers and safe placement
10. leaderboard

Every function in `simulation/` and `progression/` is pure (`(state, args) → state | effects`) with a
co-located `*.test.ts` covering happy / edge / error paths; the acceptance scenarios in each doc
(`GDD §11`, `ECOLOGY §8`, `PROGRESSION §7`, `TRAITS §6`) become gameplay-framework tests (#75, #102)
named by their scenario id (`E9`, `P3`, ...).

```ts
// evolution-module.ts (shape)
export const evolutionGameModuleFactory: GameModuleFactory = (args) => {
  let world = createWorld(args.config.seed, args.config, args.playerIds, args.random.fork('world'));
  const pendingInputs = new Map<PlayerId, GameInput>();
  return {
    submitInput: (playerId, payload) => pendingInputs.set(playerId, payload),
    reduceGameState: () => {
      world = stepWorld(world, pendingInputs, args.random);
      pendingInputs.forEach((input) => (input.sprint = false)); // sprint is edge-triggered
    },
    serializeRoomState: () => serializeWorld(world),
    addPlayer: (playerId, avatarIndex, playerName) => {
      world = addPlayerToWorld(world, { playerId, avatarIndex, playerName });
    },
    removePlayer: (playerId) => {
      world = removePlayerFromWorld(world, playerId); // dissolves the cell into detritus
    },
  };
};
```

### `packages/client/src/app/game/game-setup.ts`

`setupGame({ send, messages$, drainLatestSnapshot, host })` wires three focused modules and returns
their teardown:

- `input/input-controller.ts`: pointer (mouse/touch) and keyboard state → `GameInput` at
  `SIMULATION_TICK_HZ` via `send`; pointer screen → world through the camera; sprint on click / Space
  (edge-triggered); `1/2/3` and card clicks → `traitChoice` with the shown `offerId`; keyboard
  steering synthesises the target per [`GDD.md §4`](./docs/GDD.md#4-controls).
- `render/`: `dish-layer.ts` (dark-field background, wall rim, zones, depth particles),
  `food-layer.ts`, `cell-layer.ts` (soft-body membrane ring mesh with seeded cosmetic wobble, nucleus,
  organelles, trait visuals per [`TRAITS.md §3`](./docs/TRAITS.md#3-build-1-catalog-eight-traits-fully-specified)),
  `effects-layer.ts` (eat pulse, engulf stretch and dissolve, level-up burst, respawn fade),
  `camera.ts` (GDD §5), `interpolation.ts` (render two snapshots behind, predict own cell, reconcile
  by `sequence`; #32). Client render constants live in `render/constants.ts`; gameplay constants come
  from `@evolution/shared`.
- `frame()` each animation frame: `drainLatestSnapshot()` → interpolation buffer → layers.

### `packages/client/src/app/services/multiplayer.service.ts`

Signals: `snapshot` (typed `GameSnapshot`), `sessionConfig` (typed), `localProgress` (derived from
`snapshot.players[playerId]`), `leaderboard`, `roundPhase`, `roundTimeLeftMs`. Send method
`sendGameInput(input: GameInput)` (already `player_input`). No new lobby verbs.

### `packages/client/src/app/app.component.ts` and HUD components (#100)

- `createGame()` payload: `{ maxPlayers: ROOM_MAX_PLAYERS, seed: generateSeed(), mode: 'free_for_all',
roundDurationSeconds: ROUND_DURATION_SECONDS, endCondition: 'timer' }`; `generateSeed()` uses
  `crypto.getRandomValues` (client, not simulation code) and shows the seed in the lobby row.
- Host component mounts `setupGame` into a full-screen canvas host and overlays Angular standalone
  components: `hud-mass-level`, `dna-progress-ring`, `trait-strip`, `leaderboard-panel` (Tab holds
  the full list), `trait-offer-overlay` (three cards, timer bar, keys 1–3, never pauses),
  `respawn-overlay` (spectating the killer, countdown), `results-overlay` (final table, rematch
  countdown). All with `data-testid` attributes per `docs/UI.md` (#30).
